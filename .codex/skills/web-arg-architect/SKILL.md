# Skill: Web-ARG & 伪网页搜证解谜游戏架构师 (Diegetic Web Mystery Architect)

## 1. 叙事内生性与视觉隔离 (Diegetic UI & Visual Isolation)
- **消灭“游戏UI感”**：严禁在页面主体中使用传统游戏菜单、任务弹窗或跨站统一的公共业务顶栏。所有页面必须高度拟真现实互联网产品（如校园BBS、老旧政务/后勤公示网、B站风视频站、极简网盘）。
- **多站点独立视觉语言**：每个独立站点必须维持各自独立的 DOM 结构、配色方案与字体排版（如政务网用蓝白表格、论坛用紧凑楼层、视频站用粉白卡片+弹幕），绝不混用顶栏。
- **唯一的“第四面墙”容器**：所有跨站辅助功能（调查笔记、线索剪报、已解锁站点书签跳转、直达码输入框、调试开关）必须全部收敛在右下角半透明的【随身调查本】（`state-sync.js`）抽屉内，平时保持低透明度防遮挡。

## 2. 线索拓扑与防卡关法则 (Clue Topology & Three Clue Rule)
- **渐进式站点迷雾 (`discovered_sites`)**：初始仅暴露起点站（如论坛）。其他站点必须通过点击正文内链、搜出隐藏快照或输入 BV 号/内网码动态解锁并加入调查书签，严禁开局全量暴露破坏探索感。
- **三线索交叉验证 (Three Clue Rule)**：任何关键密码、提取码或核心推论，必须至少有 2~3 个跨站点的独立线索相互印证（例如：论坛回帖提到的时间规律 + 后勤表格的异常工号 + 视频特定秒数飘过的弹幕），严禁出现单点死胡同或无逻辑脑洞密码。
- **高光反馈闭环**：玩家首次发现关键证据、解锁新站点或解开加密附件时，调查本悬浮球需触发脉冲与红点反馈，且线索描述应客观记录“事实与疑点”，把最终拼图推理的高潮留给玩家。

## 3. 工程与回归测试铁律 (Engineering Guardrails)
- **存档向后兼容**：任何数据结构变更必须兼容旧版 `localStorage`（如 `qinghe_arg_save`），可根据已收集线索自动反推补齐新增的状态字段（如已发现站点）。
- **自动化闭环校验**：每次修改剧情、替换人名或调整交互后，必须同步更新测试套件，确保所有密码可推导、跨站链接无死链、全流程可通关。
